## 4. 时间分布

- 2017 全国表：**不含发布时间字段**，只能定位为 2017 年年中的横截面快照。
- 2018 杭州表：`publish_time` 含三种格式（当天 `HH:MM` / `N天前` / `YYYY-MM-DD`），利用 `web-scraper-order` 内嵌 Unix 时间戳恢复采集日为 **2018-05-17**，可解析率 99.5%。发布日期集中在采集日前一周内（2018-05-14 至 05-17 共 332 条，占 77%），符合招聘平台「新帖置顶」的曝光机制。

## 6. 初步发现（详见 notebook 与 figures/）

1. **样本结构**：岗位集中在北上深杭等一线城市；经验要求以 1-5 年为绝对主力（约 70%），应届与 10 年以上两端极薄——做初级/高级分化分析时必须处理**组间样本量不均衡**。
2. **薪资可解析性**：`7k-9k` 区间文本几乎全部可解析为中位数，且随经验档位单调上升，可作为岗位层级判定的辅助校验变量（`figures/02_薪资与经验.png`）。
3. **技能关键词预演**（杭州 431 个岗位的 job_desc，命中岗位数）：SQL 252、Python 178、Hadoop 127、Spark 108、Excel 91、机器学习 63、人工智能 16、深度学习 9、NLP 8、神经网络 7、TensorFlow 3、PyTorch 0。2018 年的数据岗位仍以 SQL/Excel/Hadoop 生态为主，AI 技能渗透率很低——这为本研究提供了清晰的「前 AI 时代」基线。

## 7. 局限与对研究设计的影响

1. **时间跨度不足（最关键）**：两个快照均早于 2022 年底起的生成式 AI 浪潮，单独无法回答「随时间变化」的研究问题。本阶段数据定位为**流程跑通的试点数据**，正式分析需补充 2020 年后的公开数据集，候选来源见 `docs/data_acquisition_plan.md`。
2. 2017 全国表无职位描述全文，仅有技能标签，文本挖掘深度受限。
3. 两份数据口径不同（全国多类数据岗位 vs 杭州单城市单类岗位），不能直接拼接比较，只能分别作为两个时间点的参照。
4. 数据为平台「在架岗位」快照，存在幸存者偏差（长期招不到人的岗位被高估）。
